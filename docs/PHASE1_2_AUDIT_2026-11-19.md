## 1. Dashboard error — where and what is known

- User-visible string `حدث خطأ غير متوقع` / `لم يتمكّن النظام من إكمال الطلب...` / `مرجع الخطأ` comes only from `app/admin/error.tsx:16-30`. It is the **generic fallback**: when `error.message` does not match the narrow DB regex at `app/admin/error.tsx:13`, this boundary shows the generic title. Therefore the title does **not** prove a DB outage and does **not** identify a page or exception.
- The digest `4284370173` does not exist anywhere in the repository (searched docs/logs/source). Local logs contain older, unrelated digests (`3624372193` in `docs/NAQER_ORDERING_DASHBOARD_REPAIR_REPORT.md:11-24` — an `onClick` in a Server Component, already fixed).
- Vercel runtime logs are **not available locally**: no `vercel` CLI on PATH, no `VERCEL_*` token in the environment, no MCP resource, no `.vercel/` link. Exact failing URL, timestamp, stack and deployed env key presence are still missing and must not be guessed.
- Candidate affected routes = every page under the protected shell `app/admin/(shell)/layout.tsx:9-24` (session check there), plus `app/admin/(shell)/dashboard/page.tsx` which calls 8 data operations in one `Promise.all`.

### Candidate causes (ranked, NOT confirmed)
1. `lib/prisma.ts:72-91` delegates catalog models to `lib/local-db-engine.ts` when `USE_BACKUP_DATA !== "false"` (unset also means local mode). Vercel's value is unknown. Local engine has deterministically unhandled shapes: no `ProductImage.product` relation (`app/admin/(shell)/images/page.tsx:18-21,94-98` vs `lib/local-db-engine.ts:664-813`), nested `section.category` select not resolved (`app/admin/(shell)/products/page.tsx:35-50,151`), JSON string dates used with `.toISOString()` (`audit/page.tsx:81`, `import/page.tsx:46`). Any of these throws a message that misses the admin DB regex and shows `حدث خطأ غير متوقع`. Serverless overlay writes at `lib/local-db-engine.ts:81-88` may also fail on read-only FS.
2. Live Prisma/Neon errors with wording outside the narrow regex (e.g. quota `53000`, `DATABASE_URL is not set` at `lib/prisma.ts:43-44`). Public boundary covers `53000|quota|prisma` (`app/[locale]/error.tsx:20-24`); admin boundary does not. `withDbRetry` exists but has no usages under `app/`.
3. Authorization: `lib/auth.ts:222-236` throws `FORBIDDEN: غير مصرح لك...` — also generic in this boundary. Session secret fallback at `lib/auth.ts:41-47` and HMAC fallback at `:166-202` mean a rotated Vercel `SESSION_SECRET` can invalidate cookies; however those paths normally redirect to `/admin/login`.
4. Route-local unguarded values: `new Date(params.dateFrom).toISOString()` in `orders/page.tsx:89-94`, `offer.startDate?.toISOString()` in `offers/[id]/page.tsx:66-67`.

## 2. Product options contrast — confirmed from code

- Location: `components/ProductDetailModal.tsx:12-196` (`OptionGroupSelector`, all option/add-on UI), mounted at `:1146` via `MenuView.tsx`; modal panel uses `.modal-panel { background: var(--bg) }` (`app/globals.css:907`) where `--bg: #fbf4e8` (`app/globals.css:2-23`). No dark/light theme classes or `prefers-color-scheme` exist; no Tailwind in this project.
- Root cause: **class-level dark-era colors overriding the light theme**, not inheritance and not a global selector. Exact offenders:
  - `.option-tile-name { color: #fff }` (`globals.css:3730`) on tiles with `background: rgba(255,255,255,0.035)` (`:3662`) → white on cream (~1.1:1). Primary symptom.
  - `.addon-group-name { color: var(--gold-soft) }` (`:1711`) → cream on cream (~1.2:1).
  - White-alpha radio/checkbox borders (`:3695,3712`), dark inset radio dot `#1a1514` (`:3705`), weak gold/green text (`:1726,1735,3736,3746,3755`), disabled `opacity: .45` (`:3680`).
  - `.addon-search-input` (rendered `ProductDetailModal.tsx:131` for groups with >6 options) has no CSS rule; inherits `button,input { color: inherit }` (`:50`) with default white field.
- Added in commit `4d023936` (tile UI) on top of an older light modal; other modals (OfferDetailModal, CartDrawer, CheckoutModal) never use these classes and have correct contrast.
- Affected states: normal, hover, selected/checked, fulfilled, error, disabled, focus. Affected locales: both AR (`dir=rtl`) and EN (`dir=ltr`) — no locale-specific color rules. Affected viewports: desktop `auto-fill 180px` and mobile `1fr` (`globals.css:3643-3654`) plus bottom sheet (`:2038-2060`).

### Planned minimal fix (no broad `!important`, no theme change)
Use existing design tokens (`--ink`, `--brand`, `--surface`, `--line`, `--muted`) and existing amber/green/dark-on-light values already present in `globals.css` (e.g. `:2547,2630,2666`). Scope changes to the add-on/option block only; add the missing search-input and focus states. Do not change `.modal-panel` or other pages.

## 3. Runtime evidence obtained after the static audit (2026-11-19)

- Logged into **production** with the project's existing documented OWNER account and opened every protected admin route with Playwright. Result:
  - `/admin/categories` → **HTTP 500, digest 4284370173** (exact user-reported digest).
  - Other failing routes have different digests: `/admin/products` (590958587), `/admin/products/new` (3590024385), `/admin/addons/new` (1684963152), `/admin/images` (1418566807), `/admin/import` (1193732388), `/admin/audit` (327213432), `/admin/addons/[id]` (1079665360).
  - Working: `/admin`, `/admin/dashboard`, `/admin/categories/new`, `/admin/addons`, `/admin/branches(+new,+detail)`, `/admin/offers(+new)`, `/admin/orders(+detail)`, `/admin/order-settings`, `/admin/users`, `/admin/settings`.
- Production is definitively in **local backup mode**: `/api/debug/products` returns product id `0a67d363-…` which exists in `backups/backup-naqer-verified.json` (151 products) and does **not** exist in the connected Neon DB (42 products, SELECT-only check). Therefore the failing code path is `lib/prisma.ts` → `lib/local-db-engine.ts`, not Neon/Prisma connectivity or auth.
- Reproduced locally in dev mode with the same data and captured unminified server exceptions:
  - `/admin/categories`: `TypeError: Cannot read properties of undefined (reading 'length')` in `productCount` → `s.products` undefined.
  - `/admin/products`: `TypeError: ...reading 'nameAr'` → `p.section.category` undefined.
  - `/admin/products/new`: `TypeError: c.sections is not iterable` in `getSectionOptions`.
  - `/admin/addons/new` and `/admin/addons/[id]`: `TypeError: ...reading 'category'` → `p.section.category` undefined.
  - `/admin/images`: `TypeError: ...reading 'nameAr'` at `images/page.tsx:94` → `img.product` undefined.
  - `/admin/import`: `TypeError: ...reading 'category'` at `lib/admin/import-source.ts:86` → same nested select gap.
  - `/admin/audit`: `TypeError: l.createdAt.toISOString is not a function` → JSON string dates from the local engine instead of Prisma `Date` objects.
- Direct engine probes (`scratch/inspect-local-engine.mjs`) reproduced all of the above without the browser.

### Confirmed root cause (dashboard)
`lib/local-db-engine.ts` (`resolveRelations` at `:664-820`, `pickSelect` at `:822-838`) only resolves relations supplied through `include`. Prisma queries in the dashboard also request relations through nested `select` (e.g. `sections: { select: { products: true } }`, `section: { select: { category: { select: { nameAr: true } } } }`), so the engine returns `undefined` for those fields and page code dereferences them. It also returns raw JSON strings for DateTime fields and lacks `_count`, `ProductImage.product` and `distinct` support. This was introduced by the local-mode delegation in commit `4d023936`; it is unrelated to session/RBAC and unrelated to the product-options contrast bug.

### Planned fix
Make the local engine faithful to the query shapes the application actually uses: derive relation includes from nested `select`, resolve `ProductImage.product`, support `_count` and `distinct`, and normalize DateTime strings to `Date` objects on read. No page-level try/catch, no message changes, no DB/data/auth changes.

## 4. Decisions
- The two issues are treated independently; no shared cause is assumed.
- No destructive SQL, no admin/account changes, no password resets, no data edits in Neon.
- Dashboard code must not be changed until runtime evidence identifies the actual failing path; hiding the exception or broadening the message is not acceptable.
