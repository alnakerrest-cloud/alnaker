# 05 — الوصول للحسابات وبيانات الاعتماد (Account Access & Credentials)

**المشروع:** منيو قرية الناقر (Naqer Menu)  
**تاريخ التوثيق:** نوفمبر 2026  
**درجة السرية:** وثيقة تسليم تشغيلية (تحتوي على قوالب آمنة بلا أسرار مكشوفة)  

---

## 1. آلية المصادقة وحماية الجلسات (Authentication Architecture)

- **رابط تسجيل الدخول الإداري:** `https://<domain>/admin/login`
- **لوحة التحكم:** `https://<domain>/admin/dashboard`
- **محرك التشفير:** تعتمد كلمات المرور على خوارزمية **bcrypt** مع 12 دورة تعقيد (`rounds: 12`).
- **تخزين الجلسات (Session Store):**
  - لا يتم تخزين توكن الجلسة الخام في قاعدة البيانات؛ بل يتم تشفيره عبر بصمة **Keyed HMAC-SHA256** باستخدام المتغير السري `SESSION_SECRET`.
  - يتم إرسال التوكن لمتصفح المدير كـ Cookie آمن بخواص: `httpOnly: true`, `secure: true`, `sameSite: "lax"`, `path: "/"`.
  - تنتهي الجلسة تلقائياً بعد 7 أيام، وتُلغى فوراً من السيرفر بمجرد النقر على "تسجيل الخروج".

## 2. مصفوفة الصلاحيات والأدوار (Roles & Permissions)

| الصلاحية / العملية | مالك النظام (`OWNER`) | محرر المحتوى (`EDITOR`) |
|:---|:---:|:---:|
| تسجيل الدخول للوحة التحكم | مسموح | مسموح |
| إضافة وتعديل الأطباق والأسعار | مسموح | مسموح |
| رفع وتغيير صور الأطباق على Cloudinary | مسموح | مسموح |
| تفعيل أو إخفاء الأطباق والأقسام | مسموح | مسموح |
| إنشاء وتعديل العروض الترويجية | مسموح | مسموح |
| **حذف الأطباق نهائياً من قاعدة البيانات** | **مسموح** | **ممنوع كلياً (403 Forbidden)** |
| **حذف الأقسام أو الفروع** | **مسموح** | **ممنوع كلياً (403 Forbidden)** |
| **استعراض سجلات الرقابة (Audit Logs)** | **مسموح** | **ممنوع كلياً (403 Forbidden)** |
| **تعديل إعدادات المطعم والشعار والضريبة** | **مسموح** | **ممنوع كلياً (403 Forbidden)** |

## 3. تقرير فحص حسابات النظام الافتراضية (Credentials Investigation)

تم إجراء تدقيق برمجي وقاعدة بيانات شامل للبحث عن أي حسابات افتراضية مدمجة:
1. **في الكود المصدري:** لا توجد أي كلمات مرور مكتوبة في الكود (Hardcoded Passwords).
2. **في بيئة التطوير (Dev Seeding):** يحتوي سكريبت `scripts/seed-admin.mjs` على حساب تجريبي ببريد محلي `admin@naqer-menu.local` وهو مخصص للتطوير فقط ومحمي بطلب متغير بيئة صريح `SEED_ADMIN_PASSWORD` يمنع توليده بدون قصد.
3. **في قاعدة البيانات الحالية:** تم العثور على الحسابين التجريبيين الأوليين (`admin@naqer-menu.local` و `editor@naqer-menu.local`) المنشأين في مرحلة التطوير.

### التصنيف الفني للوضع الحالي:
**4. OWNER SETUP REQUIRED (يتطلب تهيئة حساب المالك الحقيقي)**:
للإطلاق الرسمي للعميل، يجب إنشاء حساب مالك حقيقي بالبريد الرسمي للمطعم (مثل `owner@naqer.com`) باستخدام سكريبت التهيئة الآمن، وعدم تسليم حسابات تنتهي بـ `.local`.

---

## 4. إجراء تهيئة حساب المالك الرسمي (OWNER Provisioning Procedure)

يحتوي المشروع على سكريبت آمن في [scripts/provision-owner.mjs](file:///e:/real projects/naqer-menu/scripts/provision-owner.mjs) يتميز بـ:
- **عدم طباعة كلمة المرور أو الهاش أبداً** في الطرفية أو السجلات.
- **منع الكتابة فوق حساب موجود:** إذا كان الحساب موجوداً بالفعل، يرفض السكريبت الكتابة فوقه إلا بتمرير `ALLOW_OWNER_OVERWRITE=1`.

### خطوات الإنشاء للمطور أو مسؤول الإطلاق:
قم بتشغيل الأمر التالي في بيئة محمية (مع استبدال القيم بحساب المالك الحقيقي وكلمة مرور قوية لا تقل عن 12 حرفاً):

```bash
OWNER_EMAIL="owner@naqer.com" \
OWNER_PASSWORD="<STRONG_PASSWORD_HERE>" \
OWNER_NAME="إدارة مطاعم الناقر" \
node scripts/provision-owner.mjs
```

**النتيجة المتوقعة:**
```
[PROVISION SUCCESS] OWNER account "owner@naqer.com" created successfully.
Role: OWNER | Active: true
```

## 5. نموذج تسليم الحساب الآمن للعميل (Client Handover Template)

> [!WARNING]
> لا ترسل كلمات المرور أبداً في مجموعات محادثة عامة أو عبر البريد العادي بدون وسيلة تسليم آمنة. يُنصح بإرسال الرابط والبريد أولاً، وإرسال كلمة المرور عبر قناة مشفرة (مثل مكالمة مباشرة أو تطبيق One-Time Secret).

انسخ هذا النموذج واملأه للعميل:

```markdown
================================================================================
           بطاقة تسليم بيانات الدخول — منيو قرية الناقر الرقمي
================================================================================

1. رابط لوحة الإدارة:
   https://[YOUR_PRODUCTION_DOMAIN]/admin/login

2. البريد الإلكتروني للمالك (OWNER):
   [CLIENT_EMAIL_HERE]

3. كلمة المرور المؤقتة:
   [TEMPORARY_STRONG_PASSWORD]

4. الصلاحية:
   مالك النظام الكامل (OWNER)

--------------------------------------------------------------------------------
تعليمات هامة جداً لمالك المطعم:
1. فور الدخول الأول للوحة التحكم، يرجى التوجه لتغيير كلمة المرور إن رغبت.
2. احرص على عدم مشاركة بيانات حساب OWNER مع العاملين العاديين؛ وفي حال رغبت
   في تعيين كاشير أو مشرف محتوى، يمكن إنشاء حساب بصلاحية EDITOR مخصصة.
3. النظام محمي ضد هجمات التخمين، وتكرار إدخال كلمة مرور خاطئة سيقفل النموذج مؤقتاً.
================================================================================
```

## 6. إجراءات استعادة الحساب وتغيير كلمة المرور (Recovery Procedure)

في حال نسيان مالك المطعم لكلمة المرور:
1. يدخل المطور أو مسؤول السيرفر على بيئة التشغيل المصرح لها (التي تملك وصولاً لـ `DATABASE_URL`).
2. يتم تشغيل أمر التهيئة مع تفعيل خيار الاستبدال المصرح:
   ```bash
   OWNER_EMAIL="owner@naqer.com" \
   OWNER_PASSWORD="<NEW_STRONG_PASSWORD>" \
   ALLOW_OWNER_OVERWRITE=1 \
   node scripts/provision-owner.mjs
   ```
3. يقوم النظام بتحديث كلمة المرور المشفرة فوراً، وإلغاء أي جلسات سابقة كانت مفتوحة، مما يضمن أمان الحساب.
